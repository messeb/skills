# Dependency Injection

## Choosing the Right Tool

| Tool | Approach | Best for |
|------|----------|---------|
| **Wire** | Compile-time code generation | Smaller services, explicit wiring, zero runtime overhead |
| **Fx** | Runtime reflection | Larger services, modular teams, lifecycle management |

Both eliminate manual wiring in `main.go`. If your `run()` function is more than ~20 lines of `New*` calls, reach for one of these.

---

## Wire — Compile-Time DI by Google

Wire generates a `wire_gen.go` file at compile time. The generated code is plain Go — readable, debuggable, and fast.

```bash
go install github.com/google/wire/cmd/wire@latest
go get github.com/google/wire
```

### Providers

A **provider** is any function that constructs a value. Wire reads its signature to build the dependency graph.

```go
// internal/repository/provider.go
func NewUserRepository(db *sqlx.DB) domain.UserRepository {
    return &userRepository{db: db}
}

// internal/service/provider.go
func NewUserService(repo domain.UserRepository) *UserService {
    return &UserService{repo: repo}
}

// internal/handler/provider.go
func NewHandler(users *service.UserService) *Handler {
    return &Handler{users: users}
}

// internal/server/provider.go
func NewServer(cfg *config.Config, h *handler.Handler) *Server {
    return New(cfg, h)
}
```

### Injector

The **injector** is a function you write that declares what you want at the end of the graph. Wire fills in everything in between.

```go
// cmd/api/wire.go
//go:build wireinject

package main

import (
    "github.com/google/wire"
    "github.com/myorg/myapp/internal/config"
    "github.com/myorg/myapp/internal/database"
    "github.com/myorg/myapp/internal/handler"
    "github.com/myorg/myapp/internal/repository"
    "github.com/myorg/myapp/internal/server"
    "github.com/myorg/myapp/internal/service"
)

func initServer(cfg *config.Config) (*server.Server, error) {
    wire.Build(
        database.NewDB,
        repository.NewUserRepository,
        service.NewUserService,
        handler.NewHandler,
        server.NewServer,
    )
    return nil, nil   // Wire replaces this body
}
```

```bash
# Generate wire_gen.go in the same package
wire ./cmd/api/
```

Wire produces a `wire_gen.go` that looks like the manual wiring you'd write yourself — no magic at runtime.

### Provider Sets

Group related providers into a reusable `wire.ProviderSet`:

```go
// internal/repository/wire.go
var ProviderSet = wire.NewSet(
    NewUserRepository,
    NewOrderRepository,
)

// internal/service/wire.go
var ProviderSet = wire.NewSet(
    NewUserService,
    NewOrderService,
)

// cmd/api/wire.go
func initServer(cfg *config.Config) (*server.Server, error) {
    wire.Build(
        database.NewDB,
        repository.ProviderSet,
        service.ProviderSet,
        handler.NewHandler,
        server.NewServer,
    )
    return nil, nil
}
```

### Binding Interfaces

When a provider returns a concrete type but the consumer expects an interface, tell Wire which concrete type to use:

```go
var ProviderSet = wire.NewSet(
    NewUserRepository,
    wire.Bind(new(domain.UserRepository), new(*userRepository)),
)
```

### Values and Config Fields

Inject scalar values or config sub-fields with `wire.Value` or `wire.FieldsOf`:

```go
func initServer(cfg *config.Config) (*server.Server, error) {
    wire.Build(
        wire.FieldsOf(new(*config.Config), "DatabaseDSN"),
        database.NewDB,
        // ...
    )
    return nil, nil
}
```

### Using the injector in `main.go`

```go
// cmd/api/main.go
func run() error {
    cfg, err := config.Load()
    if err != nil {
        return fmt.Errorf("load config: %w", err)
    }

    srv, err := initServer(cfg)   // generated by Wire
    if err != nil {
        return fmt.Errorf("init server: %w", err)
    }

    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
    defer stop()

    return srv.Start(ctx)
}
```

## Fx — Runtime DI by Uber

Fx uses reflection at startup to resolve the dependency graph. It also manages component **lifecycle** (OnStart / OnStop hooks), making it popular in larger services with many components.

```bash
go get go.uber.org/fx
```

### Modules

Each package exposes an `fx.Module` (or a plain `fx.Option`) that provides its constructors:

```go
// internal/repository/module.go
package repository

import "go.uber.org/fx"

var Module = fx.Module("repository",
    fx.Provide(NewUserRepository),
    fx.Provide(NewOrderRepository),
)
```

```go
// internal/service/module.go
package service

import "go.uber.org/fx"

var Module = fx.Module("service",
    fx.Provide(NewUserService),
    fx.Provide(NewOrderService),
)
```

### Lifecycle hooks

Fx manages startup and shutdown order. Register hooks inside providers:

```go
// internal/server/server.go
func NewServer(lc fx.Lifecycle, cfg *config.Config, h *handler.Handler) *Server {
    srv := &Server{
        http: &http.Server{
            Addr:    cfg.HTTPAddr,
            Handler: h.Router(),
        },
    }

    lc.Append(fx.Hook{
        OnStart: func(ctx context.Context) error {
            go func() {
                slog.Info("server listening", "addr", cfg.HTTPAddr)
                if err := srv.http.ListenAndServe(); err != nil && err != http.ErrServerClosed {
                    slog.Error("server error", "error", err)
                }
            }()
            return nil
        },
        OnStop: func(ctx context.Context) error {
            slog.Info("shutting down server")
            return srv.http.Shutdown(ctx)
        },
    })

    return srv
}
```

### `main.go` with Fx

```go
// cmd/api/main.go
func main() {
    fx.New(
        config.Module,
        database.Module,
        repository.Module,
        service.Module,
        handler.Module,
        server.Module,
        fx.Invoke(func(*server.Server) {}),  // ensure Server is always built
    ).Run()
}
```

`fx.New(...).Run()` starts all lifecycle hooks, blocks until a signal is received, then calls OnStop hooks in reverse order.

### `fx.Params` and `fx.Results` — named dependencies

Use struct embedding to disambiguate multiple values of the same type:

```go
type Params struct {
    fx.In

    DB     *sqlx.DB
    Logger *slog.Logger
    Config *config.Config `name:"db-config"`  // named value
}

type Results struct {
    fx.Out

    UserRepo  domain.UserRepository
    OrderRepo domain.OrderRepository
}

func NewRepositories(p Params) (Results, error) {
    return Results{
        UserRepo:  newUserRepository(p.DB),
        OrderRepo: newOrderRepository(p.DB),
    }, nil
}
```

### `fx.Annotate` — interface binding without wrapper structs

```go
fx.Provide(
    fx.Annotate(
        NewUserRepository,
        fx.As(new(domain.UserRepository)),
    ),
),
```

### Decorate — override a dependency in a sub-scope

```go
fx.Decorate(func(db *sqlx.DB) *sqlx.DB {
    // return a test/instrumented version
    return instrumentedDB(db)
})
```

## Wire vs Fx — Side by Side

```go
// Wire — explicit, generated
func initServer(cfg *config.Config) (*server.Server, error) {
    wire.Build(repository.ProviderSet, service.ProviderSet, ...)
    return nil, nil
}

// Fx — declarative, lifecycle-aware
fx.New(
    repository.Module,
    service.Module,
    server.Module,
).Run()
```

- Wire fails at **compile time** if the graph is incomplete — no surprises at runtime
- Fx fails at **startup** with a clear error message — easier to compose dynamically
- Fx's lifecycle hooks remove the need for manual goroutine management in `main.go`
- Wire's generated code is inspectable and requires no framework at runtime

## Audit Checklist

1. **Manual wiring of more than ~5 components in `main.go`** — long chains of `New*` calls are hard to maintain and error-prone; introduce Wire or Fx
2. **Wire injector not regenerated after adding a provider** — stale `wire_gen.go` causes build failures or uses old wiring; add `wire ./...` to the Makefile and CI
3. **`wire_gen.go` not committed** — the generated file must be in version control so the project builds without the `wire` tool installed
4. **Fx providers returning errors that are not handled** — Fx propagates provider errors to startup and exits; always return typed errors so the startup log is actionable
5. **No `fx.Invoke` to anchor root dependencies** — if nothing depends on your server, Fx won't build it; use `fx.Invoke(func(*server.Server) {})` to force construction
6. **Lifecycle hooks missing `OnStop`** — registering `OnStart` without `OnStop` leaks resources (open connections, goroutines) on shutdown
7. **Concrete types injected instead of interfaces (Wire)** — binding a concrete `*userRepository` directly couples the consumer to the implementation; use `wire.Bind` to inject through the interface
8. **Fx used for a small service with 3–5 components** — Fx adds a framework dependency and startup reflection cost that is not justified for simple services; Wire or plain manual wiring is sufficient
