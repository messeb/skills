# Starting and momentum

Goal of this skill: remove the friction between deciding to do growth work and actually doing it — because the most common reason a growth programme produces nothing is not bad tactics, it is that the experiments never get run.

Use this skill when the backlog is full and nothing ships, when a growth programme is in the trough after its first failures, when work stalls on a blank page, or when a team's cycle time is dominated by delay rather than execution.

---

## 1. Why growth work stalls specifically

Growth work has properties that make it unusually easy to postpone:

| Property | Why it invites delay |
|----------|----------------------|
| **Most experiments fail** | Starting means volunteering for a likely negative result |
| **Results are public** | The whole team sees the number; a losing test feels like a personal verdict |
| **Work is optional in the short term** | Nothing breaks today if this week's experiment does not launch |
| **The first step is creative** | A blank hypothesis, a blank landing page, a blank ad — no obvious entry point |
| **Analysis feels safer than action** | More research always seems defensible, and never feels like avoidance |
| **The payoff is delayed and probabilistic** | Effort now, uncertain result in three weeks |

That last column is the diagnosis: the techniques below all work by making **the first step smaller than the resistance to it**. They do not increase motivation; they lower the height of the barrier until motivation is not required.

An important framing for a team lead: this is not a character problem. A team that consistently fails to start is usually facing an environment problem — unclear next actions, an approval chain, or the fear of a visible failure (`growth-team`). Fix those first; use the techniques below for what remains.

## 2. The action plan

The core technique: convert a goal into a **dated, timed schedule of small tasks**, so that the daily decision is no longer "should I work on this?" but "is it 09:00?".

```markdown
# Action plan — referral experiment (EXP-151)

| Date  | Time        | Task                                              | Done |
|-------|-------------|---------------------------------------------------|------|
| Mon 3 | 09:00–10:00 | Pull invite-funnel numbers, fill the observation  |      |
| Mon 3 | 10:00–10:30 | Draft hypothesis on the card                      |      |
| Tue 4 | 09:00–11:00 | Sample size + duration; agree guardrails          |      |
| Wed 5 | 09:00–12:00 | Build variant behind a flag                       |      |
| Thu 6 | 09:00–10:00 | QA on mobile + tracking check                     |      |
| Thu 6 | 14:00       | Launch                                            |      |
```

What makes it work rather than become another ignored list:

- **Specific dates and hours**, not "this week". An unscheduled task competes with everything; a scheduled one competes with nothing.
- **Tasks small enough to be unambiguous.** If you cannot picture the first thirty seconds of the task, it is too big — split it.
- **The willpower moves from the project to the checkbox.** You are no longer deciding whether to do difficult creative work; you are keeping an appointment.
- **Plan realistically, not aspirationally.** A plan that assumes six productive hours a day fails on day two and is then abandoned entirely.
- **Leave slack.** Two-thirds booked, one-third unbooked, so one interruption does not invalidate the whole plan.

The failure mode to avoid: a plan so detailed it becomes the procrastination. Twenty minutes of planning, then start.

## 3. The head-start trick

Plan **nothing** for the first day. Then start a little of the second day's work on the first day, voluntarily and without pressure.

The mechanism: the anxiety attaches to *beginning*, to the formal start with its expectations. If today is officially a non-day, then anything you do is a bonus rather than a performance — and you arrive at the real day one already in motion, with the beginning behind you.

In practice: schedule the kickoff for Tuesday and do half an hour of the easiest Tuesday task on Monday afternoon. The psychological effect is out of all proportion to the thirty minutes, because you are no longer facing a start on Tuesday; you are continuing.

Use it for anything with a heavy start: a new channel, a rewrite, a research phase, a quarter.

## 4. The weak start

Perfectionism prevents starting because the imagined finished thing is far better than anything you can produce in the first hour. The fix is to **deliberately lower the standard to zero for the first pass**.

The prompt that works: *"How would someone with no talent for this solve it?"* Then produce that — the obvious, clumsy, embarrassing version — on purpose.

| Growth application | The deliberately bad first version |
|--------------------|-----------------------------------|
| Landing page | One headline, one paragraph, one button, no design |
| Ad creative | A plain screenshot with text on it |
| Hypothesis | One ugly sentence naming the change and the metric |
| Content piece | A bullet list of everything you know, unordered |
| Onboarding flow | A sketch on paper with three boxes |

Two things then happen reliably: the bad version is easier to improve than a blank page, because critique is far easier than creation; and it is often good enough to test, which is the actual objective. A growth experiment does not need a polished artefact — it needs a variant that isolates the change (`experiment-design`).

This is the same instinct behind the riskiest-assumption test and the smoke test (`idea-validation`): the cheapest version that could produce the answer.

## 5. The alternative start

When the main task is blocked by its own difficulty, begin with an **approachable, non-creative task in the same territory**. You are not avoiding the work; you are entering it through a side door.

| Instead of | Start with |
|------------|-----------|
| "Write the experiment hypothesis" | Read last week's funnel numbers and note the biggest drop |
| "Design the landing page" | List the three objections sales hears most |
| "Write the article" | Collect the five sources and paste the quotes |
| "Plan the quarter" | Reread the strategy page and mark what has changed |
| "Choose a channel" | Fill in the BRASS table for four channels |

Analytical and mechanical tasks have almost no starting resistance because they have an obvious first move. And they drift naturally into the creative work — after twenty minutes with the funnel data you will have started forming the hypothesis without deciding to.

The discipline that keeps this honest: the alternative start must be **adjacent to the real task**, and time-boxed. Tidying the backlog is not an alternative start; it is avoidance with a productive costume.

## 6. "Just until…" and the 60-minute pact

Two techniques for low-energy days, when the problem is not starting but continuing.

**"Just until…"** shrinks the horizon to the next tiny milestone: just until this paragraph is finished, just until the variant renders, just until the tracking fires once. You are never contemplating the whole task, only the next small unit — and each completion supplies enough momentum for the next.

**The 60-minute pact** is a deal with yourself: full effort for exactly sixty minutes, and then genuine permission to stop for the day without guilt. It works for two reasons. Sixty minutes is small enough that refusing it feels unreasonable, and the permission must be **real** — if you routinely break the deal by working on, you stop believing it and the technique dies within a fortnight.

In practice, most sessions continue past the hour because starting was the hard part. But the honouring of the deal on the days it does not is what keeps it working.

Pair either with a visible timer, a single task, and no notifications. Both fail in an environment full of interruptions.

## 7. Small steps and compounding

For anything long-horizon — content, community, SEO, learning a channel — the winning pattern is a **small daily quantity that is impossible to refuse**, sustained.

| Instead of | Do |
|------------|-----|
| "Write two articles a month" | 20 minutes of writing every working day |
| "Learn paid social" | One campaign review daily, 15 minutes |
| "Build a community" | Answer one question a day in a relevant forum |
| "Improve onboarding" | One small onboarding change shipped per week |

Design rules: make the quantity **so small it survives a bad day** — this is what separates it from a resolution; attach it to an existing anchor in the day (after standup, before lunch) so no decision is required; track the streak, because visible continuity is genuinely motivating; and allow one missed day without treating the run as broken, since the all-or-nothing framing is what ends these habits.

The connection to growth practice is direct. The compounding channels — content, community, SEO, brand — pay only for teams that sustain them past the point where results are invisible (`content-and-seo-growth`). Small steps are the mechanism by which a team survives that period.

## 8. Mapping onto the experiment cycle

| Cycle stage | Where it stalls | Technique |
|-------------|-----------------|-----------|
| **Analyse** | Blank-page paralysis about what to look at | Alternative start — open the funnel report and note the biggest drop |
| **Ideate** | Nobody wants to propose a bad idea | Weak start; silent brainwriting removes exposure (`idea-generation`) |
| **Prioritise** | Endless debate to avoid committing | Timebox the scoring; Impact-Effort triage in ten minutes |
| **Design** | Over-specifying the experiment card | Weak-draft the card, then improve it once |
| **Build** | The variant is scoped to production quality | Deliberately bad version that still isolates the change |
| **Run** | Delay to "get it perfect first" | Action plan with a dated launch time |
| **Learn** | Avoiding a losing result | Schedule the write-up before the result arrives |

The last row is the sharpest one. Book the analysis slot **when you launch the test**, not when the result comes in — because a losing result is exactly when nobody volunteers to write it up, and an unwritten result is the one thing this whole practice cannot afford (`growth-process`).

## 9. When these techniques are the wrong diagnosis

Do not use motivation techniques to paper over a structural problem. Stalling is a symptom; check the cause first:

| Symptom | Real cause |
|---------|-----------|
| Nobody starts the experiment | It requires approval nobody will give (`growth-team`) |
| The team avoids the work | They do not believe it will change anything — no decisions have followed past results |
| The task never begins | The next action is genuinely undefined, not merely unpleasant |
| Constant context switching | Too much work in progress; nothing can be finished |
| Exhaustion, not resistance | Overload or burnout — a 60-minute pact is the wrong response and makes it worse |
| Repeated avoidance of one area | Missing skill or missing information, not missing willpower |

The distinction that matters: these techniques address **resistance to starting**. They do not address a blocked pipeline, a demoralised team, or someone who is unwell — and applying them there is both ineffective and unkind.

---

## 10. Anti-patterns

| Anti-pattern | Consequence |
|--------------|-------------|
| Planning in place of starting | The plan becomes the procrastination |
| Aspirational schedules with no slack | Abandoned on day two, with the whole plan discredited |
| Tasks too large to picture the first move | Resistance stays exactly where it was |
| Waiting for the polished version before testing | Weeks lost producing quality the experiment does not need |
| Breaking the 60-minute deal routinely | You stop believing yourself; the technique stops working |
| "Alternative start" used for unrelated tidying | Avoidance with a productive appearance |
| Daily habit sized for a good day | Fails on the first bad day, then ends |
| All-or-nothing streak framing | One miss ends a habit that was working |
| Motivation techniques applied to a blocked pipeline | The real blocker stays; the team is blamed for it |
| Motivation techniques applied to burnout | Actively harmful |
| Result write-up scheduled only after the result | Losing experiments never get documented |

---

## 11. Checklist

- [ ] Structural blockers checked before treating stalling as a motivation problem
- [ ] Goal converted into a dated, timed action plan with small, unambiguous tasks
- [ ] Plan realistic, with roughly a third of the time left unbooked
- [ ] Planning timeboxed so it does not become the avoidance
- [ ] Head-start used for anything with a heavy beginning — nothing scheduled on day one
- [ ] First versions deliberately weak, and good enough to test
- [ ] Experiment variants built to isolate the change, not to production polish
- [ ] Alternative entry points identified for creative tasks, adjacent and timeboxed
- [ ] "Just until…" micro-goals used on low-energy days
- [ ] 60-minute pact honoured, including the permission to stop
- [ ] Long-horizon work reduced to a daily quantity that survives a bad day
- [ ] Habits anchored to an existing point in the day; one missed day tolerated
- [ ] Result write-up scheduled at launch, before the outcome is known
- [ ] Exhaustion and burnout distinguished from resistance, and handled differently
